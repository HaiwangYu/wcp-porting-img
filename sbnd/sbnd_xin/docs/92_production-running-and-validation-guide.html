0. Read this first

The production operating point is the jsonnet file's own defaults. Since doc 68, the SBND operating point lives in exactly one place: the top-level-argument (TLA) defaults of cfg/pgrapher/experiment/sbnd/wct-pr-perevt.jsonnet (pattern recognition) and wct-clus-matching-perevt.jsonnet (clustering + Q/L matching). A bare invocation is production. The runner scripts pass only what is per-event (input, output, run/subrun/event, reality), the 15-stage PR pipeline list, and the output-file names. Anything your LArSoft job passes beyond that is a deviation. The compiled reference is committed: ref/prod-2026-09-08/prod_prjob.json.

Five non-negotiables. Each one has cost a week somewhere in this project.

  1. Compile and diff, do not read. A jsonnet comment claiming parity is not parity. The colleague-side 1-step job (sbnd/docs/5-pr-chain-in-1step.html §11) carried the comment "match the SBND production operating point" and differed from production by 160 PR knobs, because it called clus_maker.pr() directly and inherited the conservative C++ defaults. Only a compiled-config diff to zero caught it. Checklist tier T0.
  2. reality=data must match the input's lineage. The PR job re-applies the pos_offset transverse correction gated on reality. Running a data pctree as sim (or the reverse) flips scope, in-window and PID decisions wholesale (doc pr/38 r3). Every production sample here is data.
  3. Validation arms run with the debug outputs ON. An arm produced with the Bee zip and the pctree suppressed cannot be A/B gated, and the archive gate reports it as a vacuous PASS (doc 87 §5.3, §6.4). Minimal output is for production throughput, never for the run you compare.
  4. Compare archive members by content hash, never cmp the tarball. tar and zip embed mtimes; cmp "proves" regressions that do not exist. Use scripts/pr85_hash_gate.py and scripts/pr87_root_tree_diff.py (NaN-aware).
  5. Run the config tripwire before anything expensive. scripts/cfg/prod_cfg_gate.py (rc 0 = the tree you point it at still compiles to the pinned operating point; on drift it names the key).

1. The chain at a glance

3. Multi-step and multi-event running

3.1 Stage A: group mode (run_chain_group.sh, doc 81)

One wire-cell process per step per group of 16 events. Production ran ./run_chain_group.sh <reco1.root> work-<s>-d102m data --size 16 --layout perevt, with two extra flags where needed: --fsproduct 'sbnd::timing::FrameShiftInfo_frameshift__FILTERFRAMESHIFT.' for the NCpi0 file (the FrameShift product sits under a different process instance there; the dump aborts rather than guessing, so grep the branch names of every new file), and --gbase 63 for the second of the two 2000-event files so its g0 does not land on the first's. Concurrency: SBND_MAX_JOBS groups at once (default 4; each imaging process is itself TBB-threaded); prod0908 ran at 8.

Two concurrent --gbase invocations into one out_root share their runner logs. run_chain_group.sh names the per-group log $OUTROOT/.g$K.log by the internal group index, not the offset directory name g$((K+GBASE)), and its final verdict is grep -q "^[g$K] ok" on that file. Run the two halves of a two-file sample at the same time — as prod0908 did — and each invocation can read the other's success line. The group directories are offset, so no product ever collides; only the verdict does. Gate stage A on products instead: every group's events.txt non-empty, and one non-empty ql_evt<ID>/pctree-evt<ID>.tar.gz per event (doc 102, scripts/d102m_stageA_complete.sh).

Three default-OFF TLAs make it work, so a per-event run compiles byte-identically: multi_event=true (take each event's number from its tensor-set ident), rse_map={"<evt>":[run,subrun]} (a group can span runs; nueCC48 spans 12), evt_subdir='ql_evt%1%' (the runner creates the directories). With --layout perevt the group products are also split into the per-event layout, file-for-file identical to a one-event-per-process run (scripts/multi/split_group_products.py).

Fixed in toolkit 30f061ce (doc 81 §2). If your LArSoft job processes many events in one process, this is the class of bug to look for: anything keyed by an ident that is not reset per event.

Pitfalls, ordered by how silently they go wrong

  1. Entry-point bypass. Calling clus_maker.pr() from your own jsonnet inherits C++ defaults, which are default-OFF so that config selects them. Absent means pre-flip behaviour, not production. Import the operating point; diff the compiled config to zero (T0).
  2. Vacuous gates. A gate that compares nothing passes (§2.3). Read the counts the gate prints, not its exit line.
  3. Single-filename ROOT writers. SbndPrMagnifyTrackingVisitor opens tracking-pr.root RECREATE and UbooneTaggerOutputVisitor UPDATE, every event, one fixed name. A multi-event lar -n 5 leaves an 8 KB file with T_tagger and T_kine absent and rc=0 (doc 5 G9). Per-event filenames or per-event processes until the writers are made append-safe.
  4. RSE. Everything inside the graph claims run 0 / subrun 0 unless the RSE is attached (wclsTensorSetMetadataAttacher + rse_from_metadata, doc 5 G3). Only Trun carries RSE; T_tagger/T_kine do not.
  5. The DL vertex fails silently into the geometric fallback. Count the WARN (T1). The reference has zero.
  6. Bee zip was load-bearing. The in-scope set was only recorded implicitly in mabc-pr.zip; turning it off silently killed nusel-evt.tsv until save_in_scope (doc 87 §4). Before dropping an output, find its implicit consumers.
  7. Idents not reset per event in a multi-event process change physics, not just labels (doc 81 §2).
  8. In-process gojsonnet in a long job: SIGSEGV at ~120 s (doc pr/97). Precompile where you can.
  9. --fsproduct per file. The FrameShiftInfo product name changes with the producing process; the dump aborts rather than guessing. MC reco1 files also need wire_product/badmask_product/summary_product overrides (simtpc2d).
  10. The knob comment can be false. use_power_recomb=false no longer restores "the byte-identical pre-pr/10 config" after the master merge (doc 87 §8); trust the compiled diff, not the comment.
  11. Two peers, one install prefix. A concurrent rebuild swaps local/lib under a running campaign; pin the binary (copy the libs, point LD_LIBRARY_PATH at the copy) before a long arm.
  12. Never write into an existing label. work-*, ref/prod-*, abtest/snap/*, decisions and label stores are records; a new run is a new label (M13).
